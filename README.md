# 项目实时 FTP 同步工具（桌面版）

这是一个基于 Electron + Node.js 的桌面应用。支持按项目保存 FTP 配置，并在文件变化时自动同步到远程服务器。

## 功能清单

- 选择并打开任意项目目录（工作区）
- 自动加载上一次使用的项目
- 支持“历史项目”快速切换（配置区首行按钮）
- 按项目分别存储配置（项目 A / 项目 B 配置互不影响）
- 支持配置：类型（当前为 ftp）、主机、端口、用户名、密码、部署路径（远程基路径）
- 实时监听项目变更并同步
  - `add` / `change` -> 上传文件
  - `unlink` -> 删除远程文件
  - `addDir` -> 创建远程目录
  - `unlinkDir` -> 删除远程目录
- 忽略目录：`.git`、`node_modules`、`runtime`、`.idea`、`.vscode`、`dist`、`build`
- 可按项目配置额外「忽略路径」（每行一个相对路径或模式），保存后与 FTP 配置一并隔离存储
- 提供日志面板，可查看同步动作与失败原因
- **同步 Git 未暂存变更**：一键将 Git 工作区中未 `git add` 的变更上传到 FTP（不含已暂存文件）
- **提取 Git 变更**：选择未暂存 / 已暂存 / 某次 commit，将相关文件的**当前最新版本**复制到 `项目变更`
- FTP 连接失败自动指数退避重试（默认 500ms / 1s / 2s / 4s，最多 5 次）
- 同一实例内 FTP 连接串行化，监听与临时操作尽量不并行占连接，缓解 421
- **断开 FTP 连接**：一键释放本实例所有 FTP 连接（不影响其他软件/其他窗口）
- 同一项目路径仅允许一个实例执行“开始同步”（支持多开，不同项目可并行）

## 环境要求

- Windows
- 已安装 Node.js（建议 18+）
- 可使用 `npm` 命令

## 安装与启动（双击）

1. 进入应用目录 `D:\Program\Utility\FtpSyncApp`
2. 推荐双击 `start-app.vbs`（无黑框，使用 WScript 隐藏控制台启动）
3. 首次运行会自动执行 `npm install`，完成后自动启动应用
4. 后续再次双击可直接启动

### 启动入口区别

- `start-app.vbs`：推荐入口，隐藏 cmd 窗口启动 Electron。
- `start-app-hidden.bat`：兼容入口，内部调用 `start-app.vbs`，效果同上。
- `start-app.bat`：原始入口，会显示 cmd 窗口，便于排查启动问题。

## 使用步骤

1. 点击“选择项目”选择本地项目目录（或点击“历史项目”按编号快速加载）
2. 填写 FTP 配置（主机、端口、用户名、密码、远程基路径）
3. 点击“保存配置”
4. 点击“开始同步”
5. 修改项目文件，观察日志中的同步记录
6. 需要时点击“停止同步”

## FTP 连接重试与 421 提示

- 应用在建立 FTP 连接和连接异常重连时，都会先安全关闭旧连接（幂等 `close`）再重连。
- 当出现网络抖动、连接被断开、`421 Too many connections` 等可恢复错误时，会执行指数退避重试：
  - 默认最多 5 次
  - 延迟序列：500ms、1s、2s、4s（封顶 4s）
  - 遇到 `421` 时会额外延长退避时间，并主动关闭泄漏连接
- 出现 `421`/`too many connections` 时，日志会附带友好提示：建议稍后重试或减少并行同步实例。

### 421 原因与连接管理

FTP 服务器通常按 **IP + 账号** 限制同时在线连接数（常见上限 10）。以下情况都会占用连接配额：

- 本应用「开始同步」后的监听长连接
- 浏览远程目录、手动同步、Git 批量同步等临时连接
- **同一台电脑上多开本应用**（不同项目/不同窗口各占连接）
- **其他 FTP 客户端**（FileZilla、IDE 部署插件、其他同步工具等）

本应用在同一实例内采用 **连接串行化 + 单活跃连接** 策略缓解 421：

- 监听模式仅维持 **一条** 长连接
- 浏览目录、手动同步等临时操作会 **排队执行**；若监听正在运行，会先 **暂时断开监听连接**，操作完成后再自动恢复
- 所有 FTP 客户端在 `finally` 中确保 `close`，421 时额外关闭并重试

**仍可能 421 的情况：** 连接已被其他软件或其他应用实例占满。此时本应用无法从客户端侧踢掉那些会话。

### 断开 FTP 连接按钮

配置区操作按钮区提供 **「断开 FTP 连接」**（位于「停止同步」与「保存配置」之间）。

**作用（仅限本应用当前实例）：**

- 关闭本实例登记的所有 FTP 客户端（监听长连接、浏览/同步临时连接等）
- 若正在监听同步：**仅断开 FTP，不停止文件监听**；下次有文件变更时会自动尝试重连
- 日志会输出关闭数量及后续提示

**不能做到：**

- 无法断开其他软件（FileZilla、IDE 等）占用的连接
- 无法断开 **其他窗口/其他电脑** 上同一 FTP 账号的连接
- 若 421 仍出现，需等待服务器超时释放，或到主机面板/FTP 会话管理中手动清理

**建议：** 同一 FTP 账号尽量不要多开大量并发连接；需要释放配额时先在本实例点击「断开 FTP 连接」，并关闭其他 FTP 客户端。

## 项目级同步锁（允许多开）

- 应用支持多窗口/多实例同时运行。
- 但同一个项目绝对路径在同一时间只允许一个实例“开始同步”。
- 锁文件位于用户数据目录 `locks` 下，按项目绝对路径哈希生成。
- 点击“开始同步”时若锁被占用，会提示：`该项目已在其他窗口/实例同步中。`
- 点击“停止同步”或关闭应用会释放锁；异常退出后下次加锁会基于 PID 自动清理陈旧锁。

## 配置区第一行交互

- 顶部改为“当前项目目录”标题栏，右侧两个按钮：
  - `历史项目`
  - `选择项目`
- 下方以纯文本展示当前项目路径（非输入框），支持长路径自动换行。
- 点击 `历史项目` 会弹出编号选择框（最多显示前 10 条），输入编号即可加载对应项目配置并刷新本地目录。

## 忽略路径配置

在配置面板的「忽略路径」文本框中，每行填写一个相对路径或模式。保存配置后写入当前项目的 JSON 配置；开始同步时使用最新规则；若正在监听时修改并保存，会自动重启文件监听器。

**内置忽略（无需填写）：** `.git`、`node_modules`、`runtime`、`.idea`、`.vscode`、`dist`、`build`

**配置字段名：** `ignorePaths`（字符串数组，按项目保存在 `project-ftp-sync-config.json`）

**示例：**

```text
runtime/log
*.log
.env
temp
vendor/cache
```

| 写法 | 含义 |
| --- | --- |
| `runtime/log` | 项目内任意层级的 `runtime/log` 目录及其子项 |
| `*.log` | 任意目录下的 `.log` 文件 |
| `.env` | 任意层级的 `.env` 文件 |
| `temp` | 名为 `temp` 的文件或目录（任意层级） |

被忽略的路径不会触发自动上传/删除；手动右键「同步到服务器」与「同步 Git 未暂存变更」不受自定义忽略路径限制（仍会跳过内置忽略：`.git`、`node_modules` 等）。

## 同步 Git 未暂存变更

配置面板操作区提供 **「同步 Git 未暂存变更」** 按钮，用于将当前 Git 工作区中**未暂存**的变更一次性上传到远程 FTP。

**包含的文件（相对项目根目录）：**

- 已跟踪文件的未暂存修改/删除：`git diff --name-only`（删除项通过 `--diff-filter=D` 识别并触发远程删除）
- 未跟踪的新文件：`git ls-files --others --exclude-standard`

**不包含：** 已通过 `git add` 暂存、且工作区无进一步改动的文件（`git diff --cached --name-only` 中的纯暂存项不会出现在 `git diff --name-only` 中）。

**前置条件：** 已选择项目目录、已填写 FTP 配置、项目目录为 Git 仓库、本机已安装 Git 并加入 PATH。

**行为说明：**

- 无需点击「开始同步」即可使用；与实时监听独立
- 不受项目「忽略路径」配置限制，与右键手动同步一致；仍会跳过内置不可读路径
- 远程路径映射与自动同步相同：`remoteBasePath` + 文件相对路径
- 日志面板会输出找到的文件数、每个文件的上传/删除结果及成功/失败汇总

**常见提示：**

| 提示 | 原因 |
| --- | --- |
| 没有需要同步的文件 | 工作区无未暂存变更 |
| 当前项目目录不是 Git 仓库 | 所选目录未初始化 Git |
| 未检测到 Git | 未安装 Git 或未加入 PATH |

## 提取 Git 变更

配置面板操作区提供 **「提取 Git 变更」** 按钮（位于「同步 Git 未暂存变更」旁）。点击后弹出选项对话框，点选一项高亮后点「确认提取」，将相关文件的**当前工作区最新内容**复制到项目根目录下的 `项目变更` 文件夹。

**弹窗选项（自上而下）：**

| 选项 | 含义 | 收集命令 |
| --- | --- | --- |
| 未暂存变更 | 工作区未 `git add` 的修改与未跟踪文件 | `git diff --name-only` + `git ls-files --others --exclude-standard` |
| 已暂存未提交 | 已 `git add` 但尚未 commit 的变更 | `git diff --cached --name-only` |
| 某次 commit `C` | 自该提交到当前工作区的全部差异（含此后提交 + 暂存 + 未暂存相对 C 的变更），并附加未跟踪文件 | `git diff --name-only C` + `git ls-files --others --exclude-standard` |

- 前两项为固定伪选项，始终置顶；即使空仓库 / 无 commit 也显示这两项
- 其下列出最近约 40 条 commit，一行显示：`短hash  日期  提交说明`
- 交互：点选高亮 +「确认提取」（防误触）；右上角 × 或点遮罩可关闭

**典型场景：**

- 选「未暂存变更」→ 只提取当前未暂存改动
- 选「已暂存未提交」→ 只提取已 `git add` 的文件
- 选某次提交 → 提取自该提交以来到工作区最新状态改过的所有文件到 `项目变更/`（保留目录结构）

**示例：** 项目根为 `expired-human-php`，变更文件 `addons/command/xxx.php` 将复制到 `expired-human-php/项目变更/addons/command/xxx.php`。

**前置条件：** 已选择项目目录、项目目录为 Git 仓库（可为子目录，会自动解析仓库根）、本机已安装 Git 并加入 PATH（无需填写 FTP 配置）。

**行为说明：**

- 路径经 `gitRoot` → 项目相对路径解析，仅保留落在当前项目目录内的文件（避免 `python/python` 之类重复前缀）
- 目标目录不存在时自动创建；中间目录自动创建
- 单文件复制失败不阻断其余文件，失败原因写入日志
- 仅复制项目根目录内的文件，路径越界项会跳过并记录
- `项目变更` 目录自身不会被写入该目录（避免嵌套复制）
- 日志会输出所选范围、找到数量、成功/失败/跳过统计

**删除文件处理：**

- 选「未暂存变更」：若 Git 中某文件为未暂存删除，且 `项目变更` 中已有同名副本，会从 `项目变更` 中移除对应文件；若目标中本就不存在则忽略
- 选「已暂存未提交」或某次 commit：差异中包含但工作区已删除的文件会跳过并写日志

**常见提示：**

| 提示 | 原因 |
| --- | --- |
| 没有需要提取的文件 | 所选范围无变更 |
| 已跳过（当前不存在，可能已删除） | 差异中包含但工作区已删除 |
| 请选择要提取的 Git 选项 | 未点选列表项就确认 |
| 当前项目目录不是 Git 仓库 | 所选目录未初始化 Git |
| 未检测到 Git | 未安装 Git 或未加入 PATH |

## 目录面板使用

- 在“目录面板”区域可查看本地目录与远程目录。
- 本地目录：
  - 点击“刷新本地”读取当前项目目录内容。
  - 点击目录项后的“进入”进入下一级目录。
  - 点击“返回上级”回到父级目录。
- 远程目录（基于当前 FTP 配置）：
  - 点击“刷新远程”读取 `remoteBasePath`（部署路径）下的远程目录。
  - 点击目录项后的“进入”进入下一级目录。
  - 点击“返回上级”回到父级目录。
- 若 FTP 未配置或连接失败，远程目录面板会显示明确错误信息。

## 配置存储与安全说明

- 配置文件存放在 Electron 的用户数据目录下，文件名为 `project-ftp-sync-config.json`
- 配置按“项目绝对路径”作为 key 分开保存
- **密码目前为明文存储**，请确保本机账号与磁盘权限安全，必要时自行改造为加密存储
- 程序日志不会打印密码

## 常见问题

- 启动监听后日志提示“FTP 连接失败”
  - 检查主机/端口/用户名/密码是否正确
  - 检查服务器是否允许该账号登录和写入
  - 检查本机网络、公司防火墙或 VPN 限制

- 文件变更后没有同步
  - 确认已点击“开始同步”
  - 确认变更文件不在内置或自定义忽略路径中
  - 查看日志是否有具体错误
